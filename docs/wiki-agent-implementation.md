# 工具驱动 Wiki 改造记录

日期：2026-09-13。当前采用可替换 BM25 + 精确实体查找、一层跨文档摘要，以及单个 premium QA Agent 的渐进式探索与回答。按用户决定，不拆分长期 Search / Answer Agent，默认和 CLI 均不创建核验子 Agent。摘要质量、搜索算法和预算仍需真实模型实验确认。

本文包含工具驱动基线及后续摘要层改动。详细设计、工具契约和运行说明见 [跨文档摘要记录](cross-document-summaries.md)。

## 本次改动：一层跨文档摘要与单 Agent 渐进式披露

### 摘要生成与来源追溯

- 文档批次结束后，自动从带准确原文引用的受控事实生成跨文档摘要。当前用显式链接和 BM25 提议页面对，由模型判断是否存在值得总结的主题或关联；无关组合可以跳过。
- 只生成一层，不递归总结已有摘要。存储接口支持 2..4 个知识页，每个摘要必须涉及至少两个不同原始来源身份；同源副本、旧页面自由文本、摘要事实和已被明确替代的事实不能充当叶节点依据。
- 每条摘要陈述区分直接陈述与综合推导，保存支撑页面、事实 ID 和工具推导的原文引用。摘要保存在 `summaries/<child-path-hash>.md`，并记录子页面版本及相关来源版本集合。
- 每页最多选八条完整事实，组内事实输入预算为 32,000 字符；摘要最多八条陈述、正文总计最多 4,000 字符。明确标注选取范围，不宣称覆盖完整文档。

### 单个 QA Agent 的探索流程

借鉴 [Ψ-RAG 第 3.2 节](https://arxiv.org/pdf/2605.00529) 的检索—判断—改写查询—继续检索或回答循环；没有完整复现论文的向量摘要树算法。

```text
结构树 → 检索摘要 → 概览 → 陈述映射 → 选定陈述的支撑事实 → 原文核验
                                                       ↓
                                  证据不足：改写查询继续查找
                                  证据充分：回答并引用来源
```

- `wiki_search(layer="summaries"|"details"|"all")` 保留摘要与细节两种入口。实体、日期等问题可以直接搜索细节，无需强制经过摘要。
- `summary_read` 按 `overview → claims → evidence` 逐步披露。概览和陈述映射不附带原文引文；证据阶段一次展开一个陈述。知识页通过 `related_summaries` 提供返回摘要的导航。
- 最终可提交 `summary_refs: [{path, revision, claim_ids}]`，但仍须附上支撑这些陈述的原文引用。校验要求摘要陈述已展开、版本仍有效、每条支撑引文被最终引用覆盖，而且相关原文区间确实通过 `source_read` 读过。
- 默认和 CLI 使用一个 QA Agent；旧 Python 显式子任务接口仅保留兼容性。`--retrieval-model` 和 `--no-subtasks` 作为兼容参数保留，CLI 不启用委派。
- 修复了 `wiki_read(view="summary")` 只读取旧 `description` 的断点：普通知识页优先返回当前未被替代的 summary 事实。

### 更新、预算和重试

- 子页面变化或消失、相关来源版本集合变化、原文完整性检查失败，都会使摘要过期。过期摘要退出正常搜索，直接读取仅返回过期状态和子页面导航；最终回答再次校验摘要状态。
- 生成提交前复核依赖版本，拒绝生成期间已变化的材料；重建时把旧摘要保存到 `.summary-history/`。`current` 表示依赖未变化，不代表语义已核验或事实一定最新。
- `SUMMARY_BUILD_LIMIT=20` 限制每批摘要模型调用数，设为 0 可关闭该阶段。超出预算的组合记为 pending；失败可重试，未变化的成功结果和跳过决定可复用。
- 批次统计写入 `.build/summary-last-run.json`。摘要阶段失败与已完成文档分别报告，不撤销文档事实增量，也不将失败摘要缓存为成功。

检查存量语料资格、继续生成或重建摘要：

```bash
python -m llm_wiki_bench.build_summaries \
  --wiki-dir wiki_output/hotpotqa/wiki --dry-run
python -m llm_wiki_bench.build_summaries \
  --wiki-dir wiki_output/hotpotqa/wiki --limit 20 \
  --output results/hotpotqa/summary-build.json
```

## 本地验证

- 共 38 项离线回归测试通过：原基线 23 项，加上本次 15 项摘要测试。旧子任务范围和共享预算测试仅验证兼容接口。
- 新增测试覆盖单 Agent 逐步展开、缺少第二跳原文时拒绝回答及补证后成功；同源副本、递归摘要、伪造支撑拒绝；依赖过期、原文篡改、生成期间修改、历史保留、缓存与重试、多陈述选择和批次自动接入。
- 损坏摘要不影响细节搜索；过期摘要不进入正常搜索结果或最终摘要引用。
- Python 编译、CLI 入口帮助和 `git diff --check` 通过。
- 本次对现有 HotpotQA Wiki 执行摘要 dry-run：`eligible_pages=0`、`candidate_groups=0`、模型调用为 0。存量旧页面尚未重建为受控事实，未生成真实语料摘要，也未把旧页面自由文本升级为来源证据。
- 存量 HotpotQA：扫描 3,225 个旧 Markdown 文件，修复 1,870 个页面（包含 1,838 个整页围栏问题），为 1,032 份旧原文保存不可变快照。修复前文件保存在 `wiki_output/hotpotqa/wiki/.repair-backups/`。
- 修复后来源快照参与索引，共 4,238 个可检索页面。剩余 4,063 项问题记录在 `results/hotpotqa/wiki-audit-after.json`，主要是目标缺失、路径无法确定的旧链接；没有凭相似文件名创建来源关系或知识页。
- 原始审计、修复清单和修复后审计分别是 `wiki-audit-before.json`、`wiki-repair.json`、`wiki-audit-after.json`，均在 `results/hotpotqa/`。

## 尚待实验和人工核验

- 当前终端没有 `OPENAI_API_KEY` 或自定义模型端点，未执行真实 LLM 构建、问答或 EM/F1 对照；不能声称新架构已经提高答案质量或降低费用。脚本模型只验证协议与数据约束。
- Agent 分工已确定为单个 QA Agent。后续应在相同题集和可比预算下，对照有/无摘要层，以及不同检索算法、重排模型和候选数；评估答案质量、完整多跳证据、耗时和 token。
- 引文及摘要校验验证的是原文身份、版本、引用范围和支撑覆盖，不证明语义蕴含。事实抽取完整性、摘要忠实度、关系价值与更新后内容质量仍需模型核验和人工/标注集评估。原文完整阅读不等于事实抽取无遗漏。
- BM25 候选可能漏掉用词不同的相关内容；选定事实的摘要不等于全文总结。渐进式披露减少一次性输入，但已读工具结果仍会积累，尚未替代全局上下文预算管理。
- 旧页面保留为可读的旧知识，并未自动伪造为带准确位置的已核验事实。旧流程未保存的同名来源变体，需要从原始数据重新预处理和构建恢复。
- 每页写入原子化、逐文档记录完成；整个文档涉及多个页面时不是跨文件事务。中途失败可能留下已经验证过的局部增量，状态保持 partial，重试继续完成。
- 当前锁使用 Unix `fcntl`，适用于本工作区 macOS/Linux；Windows 需要替换锁实现。
